# 阶段五工作报告：工具调用型 Agent（Agentic RAG）

日期：2026-10-19　代码：`src/agent/`

## 一、目标与实现方式

把 RAG 阶段的检索/分析能力封装为 LLM 可调用的工具，由模型自主决定何时调用哪个工具——从"固定检索管线"升级为"模型规划的多步工具调用"。

**实现选型**（用户确认）：

| 维度 | 选择 |
|------|------|
| 循环实现 | 手写轻量循环，requests 直连 DeepSeek `/chat/completions` 的 `tools` 参数，不引入 LangChain/smolagents |
| 入口 | CLI + 评估优先（`run_all.py agent ask|eval`），前端后置 |
| 决策模型 | deepseek-chat |
| 范围 | 单轮多步（一次提问内最多 6 轮工具调用），多轮会话记忆留 v2 |

## 二、工具集（5 个）

| 工具 | 能力 | 复用的现有实现 |
|------|------|---------------|
| `search_report` | 全文混合检索 + 带页码引用生成 | `retriever.retrieve` + `generator.generate` |
| `get_metric` | 单公司单财年结构化指标（含出处） | `compare._best_row` / `_display` |
| `compare_companies` | 2–3 家公司同报告期对比表 | `analysis.compare.compare_peers` + `render_markdown` |
| `explain_metric` | 指标知识库解释（22 指标） | `kb.metric_kb.match_metric` + `format_entry` |
| `verify_numbers` | 数值核验（0.5% 容差） | `analysis.verify.verify_numbers` + `format_findings` |

工程细节：

- 工具 schema 的 description 动态注入 10 家公司清单与财年范围，降低模型选参错误
- 结果统一截断 4000 字符；累计工具结果超 20000 字符时注入「证据已足，请作答」
- `(工具名, 参数)` 哈希去重，重复调用直接提示模型收尾
- `arguments` JSON 解析失败不回抛，作为 tool 消息回传让模型自我修正
- 超过 `max_iters` 后最后一轮不带 tools 强制总结
- trace 记录每次工具调用的名称/参数/耗时/结果摘要，支持 `--verbose` 打印

## 三、评估结果

### 1. CFQA 分层抽样 80 题（每公司 8 题，seed 42）

同一批题、同一判分口径（数值题 1% 容差含单位换算，文本题 DeepSeek judge）下与 RAG 直答对照：

| 指标 | RAG 直答 | **Agent** | 变化 |
|------|---------|-----------|------|
| 答案准确率 | 47.5%（38/80） | **57.5%（46/80）** | **+10.0pp** |
| 数值题 | 46.8%（47 题） | **61.7%（47 题）** | **+14.9pp** |
| 文本题 | 48.5%（33 题） | 51.5%（33 题） | +3.0pp |
| 拒答/未披露 | 20 | 28 | +8 |
| 其中「拒答但 gold 有答案」 | 19 | 17 | -2 |
| 平均迭代轮数 | 1.0 | 2.15 | — |

**结论**：Agent 的收益集中在数值题（+14.9pp）——模型会主动选择 `get_metric` 查结构化库，而不是像 RAG 直答那样受限于固定路由。文本题提升有限，因为叙述题依赖检索质量本身。

### 2. 工具路由

- CFQA 80 题：期望工具出现在 trace 的比例 **98.8%**（79/80，期望由现有 `ask()` 路径离线预标）
- 10 条手写多步任务：路由分 **10/10**（期望工具全部被调用），LLM 判分 **8/10**
- 工具调用失败率 **0%**（110 次调用），平均 2.15 轮

### 3. 多步任务样例

任务「对比两面针和一心堂2022年的盈利能力，并解释差异原因」的执行轨迹：

```
1. compare_companies(codes=[600249,002727], year=2022)     → 对比表
2. explain_metric(metric=毛利率)                            → 指标定义
3. search_report(两面针2022年营收构成、亏损原因)             → 年报证据
4. search_report(一心堂2022年业务模式、盈利能力)             → 年报证据
→ 3 轮后作答：6 项指标对比 + 三条差异归因（业务结构/非经常性损益/杠杆）
```

这体现了 Agentic RAG 与传统 RAG 的核心差异：**先取结构化数据、再按需补充原文证据**，而不是一次性检索后直接生成。

## 四、实现中发现并修复的问题

| # | 问题 | 根因 | 修复 |
|---|------|------|------|
| 1 | 数值判分假阴性（「1.48 亿元」判错） | 正则要求数字至少 2 位，`1.48` 被切成 `48` | 正则改为 `[\d,，]+(?:\.\d+)?`，按有效数字位数过滤噪声 |
| 2 | 单位换算不到位（1.48 亿 vs 148,432,611.28） | 判分只尝试 10^-6..10^6 倍 | 扩到 10^-9..10^9，覆盖「亿元↔元」的 10^8 |
| 3 | Agent 数值题偏低 | `search_report` 用 top_k=4，少于 RAG 直答的 5 | 对齐为 top_k=5 |
| 4 | 评估串行太慢（54 秒/题） | API 高峰期延迟，160 题需 2 小时 | 评估脚本改 6 线程并发，约 35 分钟完成 |

## 五、局限与后续

**局限**：

- 单轮多步，无跨问题记忆（追问「那 2021 年呢」无法沿用上下文）
- DeepSeek function calling 偶有选错工具（1/80），但没有出现幻觉工具名或 JSON 坏参数
- 拒答绝对数上升（20 → 28），主要因为工具返回「未披露」时模型倾向直接拒答；不过「错误拒答」反而减少（19 → 17）
- 多步任务成本约为直答的 2 倍（2.15 轮）
- 评估使用同一 DeepSeek 判分，存在判分方差

**后续方向**：

1. 多轮会话记忆（追问场景）
2. 评估改为多轮判分取均值，降低方差
3. 把 Agent 暴露为 FastAPI `/agent` 接口 + Streamlit 对话页
4. 工具扩展：B 股/H 股多源检索、公告事件查询、跨年趋势分析
