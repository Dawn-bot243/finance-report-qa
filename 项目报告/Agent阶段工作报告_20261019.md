# 阶段五工作报告：工具调用型 Agent（Agentic RAG + 自校正检索）

日期：2026-10-19　代码：`src/agent/`

## 一、目标与实现方式

把 RAG 阶段的检索/分析能力封装为 LLM 可调用的工具，由模型自主决定何时调用哪个工具——从"固定检索管线"升级为"模型规划的多步工具调用"。

**实现选型**（用户确认）：

| 维度 | 选择 |
|------|------|
| 循环实现 | 手写轻量循环，requests 直连 DeepSeek `/chat/completions` 的 `tools` 参数，不引入 LangChain/smolagents |
| 入口 | CLI + 评估优先（`run_all.py agent ask|eval`），前端后置 |
| 决策模型 | deepseek-chat |
| 范围 | 单轮多步（一次提问内最多 6 轮工具调用），多轮会话记忆留 v2 |

## 二、工具集（5 个）

| 工具 | 能力 | 复用的现有实现 |
|------|------|---------------|
| `search_report` | 全文混合检索 + **自校正**（评估→重写→重检索）+ 带页码引用生成 | `corrective.retrieve_corrective` + `generator.generate` |
| `get_metric` | 单公司单财年结构化指标（含出处） | `compare._best_row` / `_display` |
| `compare_companies` | 2–3 家公司同报告期对比表 | `analysis.compare.compare_peers` + `render_markdown` |
| `explain_metric` | 指标知识库解释（22 指标） | `kb.metric_kb.match_metric` + `format_entry` |
| `verify_numbers` | 数值核验（0.5% 容差） | `analysis.verify.verify_numbers` + `format_findings` |

工程细节：

- 工具 schema 的 description 动态注入 10 家公司清单与财年范围，降低模型选参错误
- 结果统一截断 4000 字符；累计工具结果超 20000 字符时注入「证据已足，请作答」
- `(工具名, 参数)` 哈希去重，重复调用直接提示模型收尾
- `arguments` JSON 解析失败不回抛，作为 tool 消息回传让模型自我修正
- 超过 `max_iters` 后最后一轮不带 tools 强制总结
- trace 记录每次工具调用的名称/参数/耗时/结果摘要，支持 `--verbose` 打印

## 三、自校正检索（Corrective RAG）

在检索与生成之间插入质量评估节点，避免"检索不准也硬生成"：

```
query → 混合检索 → 评估
                    ├─ rerank top-1 ≥ 0.5 → 直接生成（零额外调用）
                    └─ 低于阈值 → LLM 复核「片段能否回答问题」
                          ├─ 充分 → 生成
                          └─ 不足 → LLM 重写查询 → 重新检索（最多 2 轮）
                                └─ 仍不足 → 返回「证据不足」，让 Agent 拒答
```

实现：[src/rag/corrective.py](src/rag/corrective.py)、接入 `search_report`（[src/agent/tools.py](src/agent/tools.py)）。
评估用混合策略：高分直接放行省调用，低分才调 LLM 复核；重写时把失败原因与已检索片段主题一并给模型，产出更具体的检索表达。

**对照评估**（同一批 40 题、同判分口径，仅切换自校正好坏）：

| 指标 | 单次检索 | **自校正检索** | 变化 |
|------|---------|---------------|------|
| 答案准确率 | 57.5%（23/40） | **65.0%（26/40）** | **+7.5pp** |
| 数值题 | 61.9%（21 题） | **71.4%（21 题）** | +9.5pp |
| 文本题 | 52.6%（19 题） | 57.9%（19 题） | +5.3pp |
| 拒答/未披露 | 13 | 14 | +1 |
| 实际触发查询重写 | 0 | 4 次 | — |
| 工具调用总数 | 50 | 53 | +3 |

**结论**：自校正主要救回「初始检索方向偏了」的题——例如把「华润双鹤2020年上半年经营业绩」重写为带"半年度报告"的查询、把「无形资产构成及变动原因」重写为带"账面原值/累计摊销/减值准备"的查询。40 题中只有 4 次重写，但带来 +7.5pp，说明低分题正是错误高发区。

## 四、多智能体辩论（尽调报告）

看多、看空两个 Agent 各自挂载全部 5 个工具**实时取证**，交替发言 N 轮（默认 3，可调 1–5），
主笔 Agent 汇总共识与分歧，输出带页码溯源的尽调报告。实现：[src/agent/debate.py](src/agent/debate.py)。

```
看多 Agent（BULL_SYSTEM）──工具取证──▶ 第1轮发言 ──▶ 看空 Agent 看到后反驳
                                                │
看空 Agent（BEAR_SYSTEM）──工具取证──▶ 第1轮发言 ──▶ 看多 Agent 看到后回应
                                                │（循环 N 轮）
主笔 Agent（MODERATOR）──读完整记录 + 核验──▶ 尽调报告（Markdown）
```

工程要点：

- **上下文控制**：每轮重建消息（system + 主题 + 最近 2 轮对方发言 + 本轮指令），不保留历史 tool 结果，避免上下文爆炸
- **异常隔离**：单方某轮发言失败不中断辩论，记录「接口异常」占位继续
- **证据纪律**：双方 system prompt 强制「只用工具证据 + 【文档名 第N页】引用 + 不编造数字」
- **主笔核验**：主笔也挂工具，可用 `verify_numbers` 复核关键数字，并如实标注核验不通过项
- **输出**：`reports/debate_{code}_{year}_{ts}.md`，含核心结论/共识/分歧/关键证据/风险提示五段

**实测**（两面针 600249 × FY2022，3 轮，321 秒）：

- 6 段发言（每段 859–1,039 字），双方各自调用工具取证
- 报告产出：核心结论「证据不足，倾向中性（略偏空）」；共识 5 条、分歧 5 条（每条含双方观点与证据强弱判断）、关键证据 14 项、风险提示 7 条
- 主笔的独立判断示例：「看多方第 2 轮用该笔资金解释经营现金流、第 3 轮又以其被剔除论证扣非干净，存在口径摇摆」「看空方'江苏实业亏损未披露'的指控被第 165 页数据证伪」
- 报告中的每个数字均带【文档名 第N页】出处，核验不通过项单独标注

## 七、P0 检索优化（语义切分 + 多查询 + 多轮判分）

### 1. 语义切分（父子块）

原方案 1 页 = 1 块，长页主题混杂、表格跨页断裂。改为：

- 按标题行（第X节 / 一、 / （一） / 编号）、段落长度、表格边界切分
- 9,810 页 → **36,583 个语义子块**（平均 3.73 块/页）
- **子块检索 → 命中后回溯父页**（整页文本供生成与【第N页】引用）
- 索引格式升级 `child_v1`（dense.npz 172MB / bm25.pkl 57MB），旧索引需 `rag build --force`

检索层评估（543 题，答案页 ±2）：

| 配置 | hit@5 | hit@10 | MRR |
|------|-------|--------|-----|
| 旧：页级索引 + 单查询（基线） | 81.8% | 87.8% | — |
| 新：子块索引 + 单查询 | 78.1% | 84.3% | 0.627 |
| 新：子块索引 + **多查询** | **82.1%** | **89.7%** | 0.640 |

**结论**：单纯换切分反而 -3.5pp（子块缺少表头/上下文，重排易误判）；改为**父页文本重排**后 hit@10 持平、hit@5 +0.7pp。切分的价值要与多查询配合才显现，组合后净 **+1.9pp（hit@10）**。

### 2. 多查询检索（Multi-Query）

LLM 生成 3 个不同角度的改写查询，与原查询一起做**加权 RRF 融合**（原查询权重 1.0、改写 0.5，避免噪音稀释）。

| 指标 | 单查询 | 多查询 | 变化 |
|------|--------|--------|------|
| hit@5 | 78.1% | 82.1% | +4.0pp |
| hit@10 | 84.3% | 89.7% | **+5.4pp** |
| 耗时/题 | 1.35s | 4.32s | +220% |

**端到端（40 题 Agent，3 轮判分）**：

| 指标 | 单查询 | 多查询 |
|------|--------|--------|
| 答案准确率 | 65.0%（26/40） | 65.0%（26/40） |
| 数值题 / 文本题 | 71.4% / 57.9% | 71.4% / 57.9% |
| 拒答 | 10 | 10 |
| 总耗时 | 246s | 358s（+45%） |

**结论**：多查询在检索层有效（+5.4pp），但 40 题端到端答案**无提升**——提升的命中页没有转化为更准的答案（top-5 已满足的题占多数，新增命中集中在 6–10 名，未进入生成上下文）。因此**默认关闭**（`multi_query=False`），保留开关供检索质量优先的场景使用。

### 3. 评估多轮判分

- `_llm_judge` 默认 **3 轮取多数**，降低单次 judge 的方差；`--judge-rounds` 可调（1 = 退化为单次）
- 本次端到端对照与检索评估均使用 3 轮判分

## 八、评估结果

### 1. CFQA 分层抽样 80 题（每公司 8 题，seed 42）

同一批题、同一判分口径（数值题 1% 容差含单位换算，文本题 DeepSeek judge）下与 RAG 直答对照：

| 指标 | RAG 直答 | **Agent** | 变化 |
|------|---------|-----------|------|
| 答案准确率 | 47.5%（38/80） | **57.5%（46/80）** | **+10.0pp** |
| 数值题 | 46.8%（47 题） | **61.7%（47 题）** | **+14.9pp** |
| 文本题 | 48.5%（33 题） | 51.5%（33 题） | +3.0pp |
| 拒答/未披露 | 20 | 28 | +8 |
| 其中「拒答但 gold 有答案」 | 19 | 17 | -2 |
| 平均迭代轮数 | 1.0 | 2.15 | — |

**结论**：Agent 的收益集中在数值题（+14.9pp）——模型会主动选择 `get_metric` 查结构化库，而不是像 RAG 直答那样受限于固定路由。文本题提升有限，因为叙述题依赖检索质量本身。

### 2. 工具路由

- CFQA 80 题：期望工具出现在 trace 的比例 **98.8%**（79/80，期望由现有 `ask()` 路径离线预标）
- 10 条手写多步任务：路由分 **10/10**（期望工具全部被调用），LLM 判分 **8/10**
- 工具调用失败率 **0%**（110 次调用），平均 2.15 轮

### 3. 多步任务样例

任务「对比两面针和一心堂2022年的盈利能力，并解释差异原因」的执行轨迹：

```
1. compare_companies(codes=[600249,002727], year=2022)     → 对比表
2. explain_metric(metric=毛利率)                            → 指标定义
3. search_report(两面针2022年营收构成、亏损原因)             → 年报证据
4. search_report(一心堂2022年业务模式、盈利能力)             → 年报证据
→ 3 轮后作答：6 项指标对比 + 三条差异归因（业务结构/非经常性损益/杠杆）
```

这体现了 Agentic RAG 与传统 RAG 的核心差异：**先取结构化数据、再按需补充原文证据**，而不是一次性检索后直接生成。

## 九、实现中发现并修复的问题

| # | 问题 | 根因 | 修复 |
|---|------|------|------|
| 1 | 数值判分假阴性（「1.48 亿元」判错） | 正则要求数字至少 2 位，`1.48` 被切成 `48` | 正则改为 `[\d,，]+(?:\.\d+)?`，按有效数字位数过滤噪声 |
| 2 | 单位换算不到位（1.48 亿 vs 148,432,611.28） | 判分只尝试 10^-6..10^6 倍 | 扩到 10^-9..10^9，覆盖「亿元↔元」的 10^8 |
| 3 | Agent 数值题偏低 | `search_report` 用 top_k=4，少于 RAG 直答的 5 | 对齐为 top_k=5 |
| 4 | 评估串行太慢（54 秒/题） | API 高峰期延迟，160 题需 2 小时 | 评估脚本改 6 线程并发，约 35 分钟完成 |

## 十、局限与后续

**局限**：

- 单轮多步，无跨问题记忆（追问「那 2021 年呢」无法沿用上下文）
- DeepSeek function calling 偶有选错工具（1/80），但没有出现幻觉工具名或 JSON 坏参数
- 拒答绝对数上升（20 → 28），主要因为工具返回「未披露」时模型倾向直接拒答；不过「错误拒答」反而减少（19 → 17）
- 多步任务成本约为直答的 2 倍（2.15 轮）
- 评估使用同一 DeepSeek 判分，存在判分方差
- **自校正只以 rerank top-1 分数为快速放行依据**：分数校准偏差会导致该重写的题未重写（40 题仅触发 4 次）；且重写只做查询层面调整，不改检索策略（如换 BM25/增加 top-k）
- 自校正的收益集中在低分题，高分题无变化，因此整体提升幅度受低分题占比限制；重写耗尽后拒答会增加（13 → 14）
- **多空辩论成本高**：3 轮约 20–30 次工具调用、6 段发言 + 1 份报告，单次 5–10 分钟；对硅基流动 API 延迟敏感（实测 API 波动时单次检索从 3 秒涨到 100 秒，已给 rerank 加 12 秒超时降级到 RRF）
- 辩论质量依赖双方检索到的证据覆盖度：若某一方检索失败，该轮论证会明显减弱；主笔只能在记录范围内汇总，无法补检
- 辩论报告的核验只覆盖可归因的指标陈述，叙述性论断（如"竞争激烈"）无法自动核验

**后续方向**：

1. 多轮会话记忆（追问场景）
2. 评估改为多轮判分取均值，降低方差
3. 把 Agent 暴露为 FastAPI `/agent` 接口 + Streamlit 对话页
4. 工具扩展：B 股/H 股多源检索、公告事件查询、跨年趋势分析
5. 自校正 v2：检索策略级纠正（重写后同时提高 top-k / 切换 BM25 权重 / 跨文档扩检），而不只是改写查询词
