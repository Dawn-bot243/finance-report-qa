# 财报 RAG 检索问答系统 · 最终总结

日期：2026-10-18（2026-10-19 补充 PDF 解析方案对比）　仓库：https://github.com/Dawn-bot243/finance-report-qa

RAG 阶段到此收尾。本文是 RAG 系统的最终总结：最终架构、最终评估结果、关键问题与取舍、遗留缺口，以及为下一阶段（Agent）准备好的资产。

## 一、做成了什么

一个可演示、可复评的财报 RAG 问答系统：**从官方披露 PDF 建成带出处的财报库，实现「提问 → 检索 → 生成带页码引用回答」的完整闭环**，以 CFQA 中文财报问答数据集（543 条有效题）为验证基准。

最终规模（10 家公司）：

| 项 | 规模 |
|------|------|
| 公司 | 10 家（CFQA test 集问题数前 10） |
| 文档 | 44 份（40 主文档 + 4 候选版本，含 3 份招股书回退） |
| 页面 | 10,683 页（逐页文本化，页码与 CFQA `答案出自` 对齐） |
| 检索分块 | 9,810 块（1 页 = 1 块） |
| 结构化指标 | 5,132 条（as_reported 3,763 / restated 1,369），69 个指标定义 |
| 指标知识库 | 22 个核心指标（FAQ 快速通道） |

## 二、最终架构

```
提问
 ├─ ⓪ 指标解释？ → 知识库直达（6ms）
 ├─ ① 公司+年份+指标？ → 结构化指标直答（8ms，带年报页码出处）
 └─ ② 其余 → 查询清洗 → 混合召回（bge-m3 稠密 + BM25 → RRF 融合）
        → bge-reranker-v2-m3 重排 → DeepSeek 生成（2–4s）
        → 行内引用【第N页】+ 数值核验 → 证据不足则拒答
```

关键组件与选型：

- **PDF 解析**：pymupdf 逐页文本层提取，页眉页脚按整份文档频率清洗。已在同一评测集上对比 pdfplumber、PaddleOCR-VL、DeepSeek-OCR 三种替代方案，**pymupdf 72.2% 最优**（详见 [PDF解析方案对比_20261018.md](PDF解析方案对比_20261018.md)）
- **检索**：硅基流动 bge-m3 嵌入（1024 维）+ jieba BM25 关键词召回，RRF 融合后经 bge-reranker-v2-m3 重排。向量存 numpy 稠密矩阵（放弃 Chroma，见问题 1）
- **生成**：DeepSeek chat（requests 直连），仅依据检索上下文作答，行内引用【第N页】，数字必须出现在所引页面
- **结构化直答**：命中「公司+年份+指标」直接查 metrics 表作答，**as_reported（原文披露口径）优先、restated（API 重述口径）兜底**，三重精度守卫防答非所问（分部/同比/别名碰撞）
- **数值核验**：回答中「指标=数值」陈述与结构化库原值比对（容差 0.5%），不一致追加「⚠️ 待核实」
- **出处信息链**：`metrics → (doc_id, page_no, source_text 原文片段) → pages.text`，API 值与 PDF 原文容差匹配后回填出处，不符只链接不引错页
- **交付形态**：FastAPI 7 个接口 + Streamlit 三页签前端；CLI 一键 `run_all.py` 幂等可重跑

## 三、最终评估（CFQA 543 题）

| 指标 | 结果 |
|------|------|
| 检索命中 hit@5 / hit@10 | **81.8% / 87.8%** |
| 数值题准确率 | **86.2%**（58 题） |
| 文本题一致率（LLM 判分） | **60.0%**（485 题） |
| 结构化直答占比 | 12.5%（数值题 4 → 58 题） |
| 拒答/未披露 | 118 题（证据不足时宁缺毋错） |
| 数据质量门 | 四道门全 PASS（答案命中 92.7%） |

按分组：

| 分组 | 题数 | hit@10 | 文本题一致 | 拒答 |
|------|------|--------|-----------|------|
| 原有 5 家 | 321 | **92.8%** | 72.4%（210/290） | 52 |
| 新增 5 家 | 222 | **80.6%** | 41.5%（81/195） | 66 |

按公司：恒玄科技 100%、瑞联新材 100%、建龙微纳 98.3%、芯海科技 96.3%、泰瑞机器 91.8%、两面针 91.1%、一心堂 88.3%、昊海生科 83.1%、伊泰B股 72.2%、华润双鹤 61.4%。

**结论**：检索能力随规模扩展保持稳定（原有公司子集 92.8%）；问答质量方差主要来自**数据源覆盖**而非架构——低分集中在 B 股（伊泰）、叙述题（华润双鹤）。

## 四、关键问题与取舍

| # | 问题 | 解决 |
|---|------|------|
| 1 | Chroma 在 Windows/Py3.13 上 HNSW 索引反复损坏 | 改用 numpy 稠密向量（9,810×1024 内存检索），功能等价、零依赖、更稳定 |
| 2 | rerank API 返回未排序 | 显式降序处理 |
| 3 | 查询模板噪音稀释向量（公司名/年份/「有哪些」） | 查询清洗，公司年份交给元数据过滤，hit@10 从 4/10 提到 9/10 |
| 4 | 结构化直答答非所问（分部按总量、同比答绝对值、别名子串碰撞） | 三重精度守卫，不满足即回退 RAG |
| 5 | API 是重述口径、CFQA 答案是原文口径 | `basis` 维度（as_reported/restated），检索优先原文值 |
| 6 | API 数据无页码出处 | 与 PDF 原文容差匹配后回填文档+页码，不符只链接不引错页 |
| 7 | hit@10 名不副实（评估默认 top_k=5） | 评估显式 top_k=10，结构化/FAQ 视为命中 |
| 8 | 数据集噪声：公司名错配、答案含推导值、「未披露」类答案 | `name_ok` 隔离错配题；命中校验优先原文数字；未披露/版本差异不计 gate2 分母 |
| 9 | 数值题覆盖面小（仅 4 题） | 新增 11 个资产负债表科目，结构化直答占比 1.2% → 12.5% |
| 10 | PDF 解析要不要换多模态 OCR 模型 | 同一评测集（543 题 / 426 答案页）对比四方案：pymupdf 72.2% ≈ DeepSeek-OCR 71.6% ≈ pdfplumber 71.5% > PaddleOCR-VL 67.2%。有文本层的年报规则提取无损，维持 pymupdf；OCR 留给扫描件 |

## 五、遗留缺口（也是 Agent 阶段的起点）

1. **B 股数据源缺失**：东财/baostock 对伊泰B股（900948）无数据；CFQA 部分答案来自 H 股报告，B 股年报中无对应数字 → 拒答 32/54。需要多源检索（H 股/交易所公告）
2. **叙述题一致率低**：华润双鹤 12/44，问题多为研发人员占比、税负结构等叙述性内容，检索命中也常答「未披露」。需要查询改写与更细粒度切分
3. **评估判分方差**：同一 DeepSeek 判分，两次运行有数个点波动。需多轮判分取均值
4. **DataSinking 覆盖不均**：伊泰、华润等公司全文 Markdown 不完整，兜底源可靠性有限
5. **工程化限制**：单机单进程（SQLite + 进程内缓存）、无鉴权/限流、无流式输出
6. **扫描版 PDF 未覆盖**：当前 44 份文档均带文本层；若扩充到纸质年报扫描件，需接入 OCR。已验证 DeepSeek-OCR 在文本层 PDF 上可追平规则提取（71.6% vs 72.2%），是扫描件的首选备选

## 六、为 Agent 阶段准备好的资产

RAG 阶段沉淀的资产可直接作为 Agent 的工具层复用：

- **现成工具接口**：FastAPI 已有 问答 / 指标查询（含出处）/ 同业对比 / 指标解释 / 数值核验，天然对应 Agent 的 tool schema，补充描述即可挂载
- **带出处的知识底座**：10,683 页带页码文本 + 5,132 条带出处的结构化指标 + 检索/重排组件，是 Agent「查证」能力的物质基础
- **精度守卫与核验机制**：结构化直答守卫、数值核验、证据不足拒答，可平移到 Agent 的工具调用与回答校验环节
- **评估基础设施**：CFQA 543 题评估集 + 检索命中/数值/文本三重判分 + 四道数据质量门，可用于评估 Agent 端到端效果
- **解析方案的定量结论**：四方案对比（543 题 / 426 答案页）确认 pymupdf 对文本层 PDF 最优、DeepSeek-OCR 为扫描件备选，后续扩容不必重复论证

Agent 阶段需要新增的（初步）：多轮对话状态、工具调用协议与规划、B 股/H 股多源检索、查询改写、流式输出，以及面向多步任务的评估方法。
