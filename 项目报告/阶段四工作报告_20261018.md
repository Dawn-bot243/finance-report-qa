# 阶段四工作报告：系统集成与评估（2026-10-18）

## 一、目标

把前三个阶段的能力封装为可演示的 Web 应用，并给出完整评估指标。

## 二、交付物

```
src/api/server.py          # FastAPI 后端（7 个接口）
app/streamlit_app.py       # Streamlit 前端（三个页签）
scripts/api_smoke.py       # API 冒烟与延迟测试
run_all.py serve           # 一键启动后端
```

## 三、后端（FastAPI）

启动：`python -X utf8 run_all.py serve --port 8000`

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/health` | 健康检查（文档 24 份 / 页面 5,807 / 指标 2,599 条） |
| GET | `/companies` | 5 家公司列表 |
| POST | `/ask` | 问答，返回路径（faq/structured/rag）、回答、引用、数值核验 |
| GET | `/kb?question=` | 指标解释（知识库） |
| GET | `/metrics?code=&year=&keys=` | 单公司单财年指标（含出处页码/口径） |
| GET | `/compare?codes=&year=&metrics=` | 同业对比（markdown + 结构化行数据） |
| GET | `/metric_defs` | 全部指标定义 |

设计要点：问答复用阶段二/三核心模块，各请求独立 SQLite 连接；检索索引（BM25/稠密向量）进程内缓存；CORS 全开便于本地前端联调。

## 四、前端（Streamlit）

启动：`streamlit run app/streamlit_app.py` → http://localhost:8501

三个页签：
1. **财报问答**：示例问题快捷按钮；显示回答路径（指标解释 / 结构化直答 / 检索生成）、回答正文、引用页码、数值核验警告、检索详情
2. **指标查询**：选公司与报告期，表格展示 15 项核心指标（数值、口径、出处）
3. **同业对比**：选 2–3 家公司 + 报告期 + 自选指标，渲染对比表（含可比性说明），支持 CSV 下载

选择 Streamlit 而非 Vue 3 的原因：纯 Python、零构建链路、与现有技术栈一致，演示与迭代成本最低；后端已解耦，后续换 Vue 不影响接口。

## 七、问题记录：财报问答「提问」无响应（已修复）

**现象**：在 Streamlit 前端点击「提问」按钮没有任何反应（无报错、无回答、无加载提示）。

**根因**：Streamlit 组件状态重置。

- 原实现 `question = st.text_area("问题", value=clicked or "")`，把动态变量传给 `value`
- 点击「提问」触发表单重跑时，`clicked` 重新变为 `None`，`value` 被重新计算为空字符串，**输入框内容被清空**
- 随后 `if st.button(...) and question.strip()` 读到空串，条件为假，于是什么都不发生
- 走示例问题按钮的路径必现（`clicked` 在两次重跑间从示例文本变回 `None`）

**修复**：
1. 输入改用 `st.session_state["ask_question"]` 承载，示例按钮只写状态，不再参与 `value` 计算
2. 「提问」改用 `st.form` + `st.form_submit_button`，表单提交天然保留组件状态
3. 补充空输入提示（`st.warning("请输入问题后再点击提问")`）
4. 顺带替换 Streamlit 已废弃的 `use_container_width` 参数（改为 `width="stretch"`）

**验证**：使用 Streamlit 官方测试框架 `AppTest` 模拟真实交互：
- 手动输入「两面针2019年营业收入是多少」→ 点击提问 → 返回「结构化指标直答」与答案 ✓
- 点击示例「毛利率是什么」→ 输入框自动填入 → 点击提问 → 返回「指标解释（知识库直达）」✓

## 八、已知限制

1. 单机单进程演示架构（SQLite + 进程内缓存），不适合并发生产流量
2. Streamlit 为演示界面；生产可换 Vue 3，后端接口无需改动
3. RAG 回答 2–4 秒延迟主要来自 LLM 生成；检索与重排约 0.3–0.5 秒
4. 评估文本题判分使用同一 DeepSeek 模型，存在判分偏差；数值题样本量小（4 题）
5. 5 家公司跨行业，「同业对比」验证的是机制，不是真实同行分析
6. 未做用户鉴权、限流与审计
