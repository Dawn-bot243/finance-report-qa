# 这个项目是什么？—— 小白也能懂的说明

> 一句话：**它能让 AI 读懂几十份上市公司年报，回答财务问题，并且每次回答都告诉你"这个数字是从哪一页看来的"。**

---

## 一、先说说问题：为什么不能直接问 ChatGPT？

你问 ChatGPT：「两面针 2022 年的营业收入是多少？」

它可能会给你一个数字，但你没法确定：
- 这个数字是它真的查过，还是**编的**？
- 它说的是 2022 年，会不会记成 2021 年？
- 即使数字对了，**出处在哪里**？谁能为这个数字负责？

在财务、投资、审计这类场景里，**一个查不到出处的数字等于没有价值**。专业人士要的不是"一个答案"，而是"一个可以核对的答案"。

所以这个项目要解决的核心问题是：

> 让 AI 的回答**有据可查**——每个数字都能翻到年报的某一页。

---

## 二、核心思路：把「闭卷考试」变成「开卷考试」

普通的大语言模型（像 ChatGPT）像一个**记忆力很好的学生，但只能闭卷答题**——它记住的东西可能过时、可能记错，还说不清自己是从哪本书上看来的。

这个项目做的是：**给它准备一整个书架，让它开卷考试。**

具体做法分两步：

1. **把书准备好**：下载 10 家上市公司的年报 PDF（44 份，共 10,683 页），拆成一页一页的文字，存进数据库。
2. **让它查着书答题**：用户提问时，先从书架上找出最相关的几页，再让 AI **只看这几页**回答，并标出页码。

这种方法有个专门的名字，叫 **RAG**（Retrieval-Augmented Generation，检索增强生成）——"先检索，再生成"。

---

## 三、五个阶段，像盖房子一样

| 阶段 | 盖房子的类比 | 实际做了什么 |
|------|------------|------------|
| 一、数据 | 打地基、搬砖 | 从巨潮资讯网下载年报 PDF，逐页提取文字，整理出 5,132 条财务指标 |
| 二、RAG 问答 | 建图书馆和检索系统 | 把 9,810 页文字变成"可以按意思搜索"的形式，提问时先找相关页再让 AI 回答 |
| 三、分析 | 配一套工具箱 | 指标解释（ROE 是什么）、两家公司对比、数字核对 |
| 四、界面 | 装修门面 | 网页版界面（提问页、指标查询页、对比页），后端接口 |
| 五、Agent | 请一个会自己干活的助理 | AI 自己决定用哪个工具、查几次，甚至能开"多空辩论会"写报告 |

## 四、几个关键概念，用生活例子解释

### 1. 向量检索（Embedding）—— "按意思找，而不是按字找"

传统搜索是"关键词匹配"：你搜"营业收入"，只出现包含这四个字的地方。

**向量检索**是把每段文字变成一串数字（像给每段文字拍一张"含义指纹"）。意思相近的文字，指纹也相近。

好处：你问"这家公司去年赚了多少钱"，即使原文写的是"归属于母公司股东的净利润"，也能找到——因为**意思一样**。

**为什么要切小块？** 一页年报可能有 1500 字，里面混着好几个话题。如果整页一起比对，就像拿一张全家福去匹配"找穿红衣服的人"——信息太杂。所以系统把每页再切成平均 3.7 个小段（共 36,583 段），用**小段去搜索**，找到后再**回到整页**去读上下文。这叫"父子块"：小段负责精准定位，整页负责完整理解。

### 2. 混合检索 —— "两只眼睛一起看"

只用向量检索（按意思）会漏掉精确的数字和专有名词；只用关键词检索（BM25）又不懂同义词。

所以项目同时用两种方法找，再把两份结果**合并**（这个合并算法叫 RRF），再让一个"裁判模型"（reranker）重新打分排序。

打个比方：两个图书管理员各自推荐 10 本书，合并名单后，再由一位资深馆长挑出最值得看的 5 本。

### 2.5 多查询检索 —— "换个说法再问一遍"

同一个问题，用不同说法问，可能查到不同的资料。比如：
- "两面针研发投入多少"
- "两面针研发费用和研发人员情况"
- "两面针研发投入占营业收入比例"

系统可以让 AI 自动生成几个不同角度的问法，**一起检索、合并结果**。这能提高"找到正确那一页"的概率（实测提升 5.4 个百分点）。

但也要付出代价：检索次数变成 3–4 倍，速度变慢。而且实测发现——**找得更准，不代表答得更好**（见下面的效果说明）。所以这个功能默认关闭，需要时可以打开。

### 3. 结构化指标 —— "除了翻书，还直接查表"

年报里很多数字是标准化的（营业收入、净利润、ROE……）。与其让 AI 每次去 PDF 里找，不如提前整理成一张**数据表**。

所以系统里有两条路：
- **查表**：问"某公司某年某指标"，直接查表，毫秒级返回，带页码出处
- **翻书**：问开放式问题（"研发投入情况如何"），才去检索原文

这就像问图书管理员"某本书第几页写了什么"（查目录）vs "帮我总结一下这本书讲了什么"（通读）。

### 4. Agent —— "会自己决定用什么工具的助理"

普通问答系统是**固定流程**：一定先检索、再生成。

**Agent** 不一样：它拿到问题后，自己判断——
- 这是不是该查指标表？
- 要不要先对比两家公司？
- 检索结果不够好，要不要换个说法再查一次？

就像一个会干活的助理，而不是一条流水线。

### 5. 自校正检索 —— "查不到就换个问法"

有时第一次搜索没找对方向。比如问"华润双鹤 2020 年上半年业绩"，直接搜可能搜到全年数据。

**自校正**的做法是：
1. 先检查"找到的内容真的能回答这个问题吗？"
2. 如果不能，让 AI **换个说法重新搜**（比如加上"半年度报告""上半年"）
3. 最多试 2 次，还不行就老实说"证据不足"，**而不是硬编一个答案**

这体现了一个原则：**宁可说不知道，也不瞎编。**

### 6. 多智能体辩论 —— "开一场多空辩论会"

最后加的功能：让两个 AI 分别扮演**看多**（找优点）和**看空**（找风险），各自查资料、互相反驳，辩论 3 轮；最后再由一个"主笔 AI"总结成一份尽调报告，列出：
- 双方都同意什么（共识）
- 双方吵什么（分歧）
- 关键证据和页码
- 风险和没查到的东西

好处：单一 AI 容易"顺着一个方向说"，两个对立角色能互相挑错，结论更平衡。

## 五、效果怎么样？（用大白话）

项目用了一个公开的评测集 **CFQA**（中文财报问答数据集），里面有真实的问题和标准答案。

| 指标 | 数字 | 大白话 |
|------|------|--------|
| 检索命中率（Top-10） | **87.8%**（最新优化后检索层达 89.7%） | 100 道题里，88–90 道能在前 10 个候选页里找到正确的那一页 |
| 数值题准确率 | **86.2%** | 问具体数字的题，86% 答对 |
| 叙述题一致率 | **60.0%** | 开放性问题（研发情况、业务模式）只有 60% 与标准答案实质一致 |
| 拒答 | 118 / 543 | 拿不准时老实说"证据不足"，而不是硬答 |

**一句话总结**：**查数字很强，讲故事一般。** 这也是这个项目下一步要重点改进的地方。

**关于"切小块 + 多查询"的实测**（面试常被追问）：
- 把页面切成小段来搜，单独用反而让命中率降了 3.5 个百分点——因为小段缺少表头等上下文，容易误判
- 配合"多查询"一起用，检索命中率提升到 89.7%，超过原方案
- 但端到端答案准确率**没有变化**（65% vs 65%）——说明"找得更准"没有转化成"答得更好"
- 这个结论本身很有价值：**优化要看最终指标，不能只看中间指标**

**关于判分**：开放式问题靠另一个 AI 打分，单次打分会有波动。所以改成**每题打分 3 次、取多数**，让评估结果更稳定。

另外还做了几组对照实验：

- **Agent vs 普通问答**：同一批 80 题，Agent 答对 57.5%，普通问答 47.5%——AI 自己选工具比固定流程高 10 个百分点
- **自校正检索**：40 题里，带"查不到就换问法"的版本 65%，不带的 57.5%
- **PDF 解析方案**：比较了 4 种解析方式，最终确认现有方案最适合这批有文字层的年报

## 六、怎么用？

### 网页版（最直观）

```bash
# 1. 启动后端
python -X utf8 run_all.py serve --port 8000

# 2. 启动前端（另开一个终端）
streamlit run app/streamlit_app.py

# 3. 浏览器打开 http://localhost:8501
```

界面有四个页签：
- **财报问答**：普通提问
- **指标查询**：查某公司某年的指标表
- **同业对比**：选 2-3 家公司对比
- **智能体问答**：复杂问题（对比、归因），AI 自己调工具，还能看到它调了什么

### 命令行

```bash
# 问一个问题
python -X utf8 run_all.py rag ask --question "两面针2019年营业收入是多少"

# 让 Agent 回答复杂问题
python -X utf8 run_all.py agent ask --question "对比两面针和一心堂2022年的盈利能力并解释差异"

# 多空辩论出尽调报告
python -X utf8 run_all.py agent debate --company 600249 --year 2022 --rounds 3
```

## 七、它做不到什么？（诚实版）

1. **只覆盖 10 家公司、2019–2022 年**——不是全市场
2. **叙述题还不够好**（60%）——问"研发人员结构""行业竞争格局"这类问题，答案质量一般
3. **B 股数据有缺口**——伊泰 B 股的部分答案在 H 股报告里，B 股年报中根本不存在，所以系统会拒答
4. **需要联网调用大模型 API**——断网或额度用完就不能用
5. **不是投资建议**——它只负责"找到并引用事实"，不判断公司值不值得买

## 八、一分钟读懂版

> 这是一个"**给 AI 配一个可查证的书架**"的项目。
>
> 它把上市公司年报拆成可搜索的页面，提问时先找到相关页，再让 AI 只依据这些页面回答，并标注页码。
>
> 在此之上，它还能自己决定用哪个工具（Agent）、查不到时换问法（自校正）、以及让两个 AI 开辩论会写尽调报告（多智能体）。
>
> 它擅长查具体数字（准确率 86%），不擅长总结开放性问题（60%）——这也是下一步要改进的地方。
